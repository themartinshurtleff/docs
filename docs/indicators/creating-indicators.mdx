TradeNet Terminal runs custom indicators written in Lua. Scripts load from a folder on disk, hot-reload on save, and read everything the chart knows: OHLCV, footprint levels, delta, CVD, open interest, liquidations. If the built-ins (SMA, EMA, RSI, Bollinger, Volume Delta, OI CVD, TPO Profile) don't cover what you trade, build it yourself.

## Where scripts live

The terminal scans one folder for `.lua` files:

| Platform | Path |
|----------|------|
| Windows | `%APPDATA%\tradenet-terminal\indicators\` |
| macOS | `~/Library/Application Support/tradenet-terminal/indicators/` |

On first run the terminal writes 5 bundled examples there: `sma_crossover.lua`, `rsi.lua`, `volume_delta.lua`, `bollinger_bands.lua`, `oi_cvd.lua`.

<Tip>
Study the bundled examples first. They cover overlays, panels, settings, and the common data access patterns. Copy one and modify it instead of starting from a blank file.
</Tip>

## Script anatomy

Every indicator is one Lua file that returns a table. Here is a complete working SMA:

```lua
return {
    name = "My SMA",
    mode = "overlay",
    settings = {
        period = { type = "int", default = 20, min = 2, max = 200, label = "Period" },
        line_color = { type = "color", default = "#c9a84c", label = "Color" },
    },
    compute = function(ctx)
        for i = 0, ctx.candle_count() - 1 do
            local v = ctx.sma("close", ctx.settings.period, i)
            if v then ctx.set_value(i, v) end
        end
    end,
    draw = function(ctx)
        local prev = nil
        for i = 0, ctx.candle_count() - 1 do
            local v = ctx.sma("close", ctx.settings.period, i)
            if v and prev then
                ctx.draw_line(i - 1, prev, i, v, ctx.settings.line_color, 1.5)
            end
            prev = v
        end
    end,
}
```

Four parts:

- `name`: what shows in the indicator browser.
- `mode`: `"overlay"` or `"panel"`. See below.
- `settings`: declares the knobs users can tune. Optional.
- `compute` and `draw`: the two functions the terminal calls. Both receive a `ctx` object that exposes the full API.

## The two modes

<AccordionGroup>
<Accordion title="overlay">
Draws directly on the price chart. Y values are prices. Use this for moving averages, bands, VWAPs, levels, and anything that lives in price space.
</Accordion>
<Accordion title="panel">
Gets its own sub-panel below the chart with its own scale. Y values are whatever you want: RSI from 0 to 100, delta in volume units, OI in USD. Panel indicators auto-render the primary series (set via `ctx.set_value`) as a line and show a hover readout of all series values. You get a working panel from `set_value` alone, with an empty `draw` body. The `draw` function must still be declared, even if it does nothing.
</Accordion>
</AccordionGroup>

## Settings

Four types: `int`, `float`, `bool`, `color`. Each setting shows up in the indicator's settings pane in the terminal.

```lua
settings = {
    period = { type = "int", default = 14, min = 2, max = 500, label = "Period" },
    mult = { type = "float", default = 2.0, min = 0.1, max = 10.0, label = "Multiplier" },
    show_bands = { type = "bool", default = true, label = "Show Bands" },
    up_color = { type = "color", default = "#4caf50", label = "Up Color" },
}
```

Read values through `ctx.settings.period` and so on. Settings are per-pane, per-indicator. The same script on two panes can run with different values.

## Lifecycle

1. `compute` runs when chart data changes. The terminal checks for changes every 250ms.
2. `draw` runs right after `compute`.
3. Rendering replays the cached draw commands every frame. Your Lua does not run per frame.

<Warning>
The series store is cleared before every `compute`. Populate the full series every run. Do not assume values from the previous run are still there.
</Warning>

## Hot reload

Save the `.lua` file and the indicator list refreshes within about a second. No restart needed.

<Warning>
An indicator already on a chart keeps running its old code after you save. Toggle it off and on to pick up your edits.
</Warning>

## Indexing rules

Everything is 0-based. Index 0 is the oldest candle. `ctx.candle_count() - 1` is the live candle.

```lua
for i = 0, ctx.candle_count() - 1 do
    local c = ctx.close(i)
    if c then
        -- safe to use c
    end
end
```

<Warning>
`ipairs` and `#` do NOT work on `ctx` tables. Use explicit loops. Out-of-range reads return `nil`, so always nil-guard.
</Warning>

## Errors and limits

A script error shows as a badge on the indicator instead of crashing the terminal. Hard limits:

| Limit | Value |
|-------|-------|
| Compute time | 100ms per run |
| Draw time | 50ms per run |
| Memory | 32 MB |
| Draw commands | 10,000 per draw call |

Blow a limit and the indicator stops with an error badge. The terminal keeps running.

## Your first indicator

<Steps>
<Step title="Create the file">
Make a new file in your indicators folder, for example `my_sma.lua`.
</Step>
<Step title="Write the script">
Paste the SMA example above, or copy a bundled example and edit it.
</Step>
<Step title="Save">
The terminal picks it up within about a second.
</Step>
<Step title="Open the indicator browser">
Your script appears in the list under the name you set.
</Step>
<Step title="Toggle it on">
The indicator attaches to the active pane and runs.
</Step>
<Step title="Tune settings">
Open the indicator's settings pane and adjust your declared values. Changes apply immediately.
</Step>
</Steps>
